# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer](https://semver.org/lang/ru/).
Версия — тег `v<версия>`; она же в `version` файлов `.claude-plugin/plugin.json` и `package.json`.

Записи — о том, что заметит тот, кто поставил плагин: поведение хуков и охраны, команды `forge`, скиллы и
агенты, формат профиля. Правка без видимого эффекта сюда не пишется. Разделы версии — **Added**, **Changed**,
**Fixed**, **Removed** и **Обновление**: что сделать при переходе на версию (профиль, переопределения,
несовместимости).

## [Unreleased]

### Added
- forge работает в дополнительном git worktree (например, `.claude/worktrees/<имя>` от Claude Code): если в нём
  нет своего `.forge/profile.json`, берётся профиль основного checkout — охрана, проверка, линт и
  переопределения маршрутизации работают как там, а не со встроенными значениями. Профиль самого worktree
  важнее; состояние, журнал правок и планы `.forge/work/` остаются своими в каждом worktree. `forge doctor` и
  начало сессии пишут «профиль из основного checkout <путь>». См. [«Профиль в worktree»](docs/ru/profile.md#профиль-в-worktree).
- Нативный Windows. Команды профиля (формат, линт, проверка) запускаются через Git Bash из Git for Windows, а
  не через `/bin/sh`: путь берётся из `CLAUDE_CODE_GIT_BASH_PATH`, затем рядом с `git --exec-path`, затем из
  `Program Files` и `LocalAppData`. На Windows `forge doctor` показывает строку `✓`/`✗` про Git Bash. Без Git
  for Windows охрана работает, а проверка, формат и линт **пропускаются, а не падают**: это проблема окружения,
  которую модель не исправит в своём коде. `Stop` и `PostToolBatch` не блокируют и не зовут `debugger`, серия
  падений не растёт, `verify.ok` в состоянии — `null`, пользователь получает одно уведомление (запоминается в
  `shell_missing_notified`, сбрасывается, когда команды снова выполняются); курсор проверки при этом стоит на
  месте, и правки за это время проверятся, когда Git Bash появится. `forge verify` печатает
  `SKIPPED: …` и выходит с кодом 4 (`--json` добавляет `"shell_missing": true`). Установка — в разделе Windows
  [README.ru.md](README.ru.md#windows); синтаксис команд — [`commands`](docs/ru/profile.md#поля-профиля);
  подробности — [«Какая оболочка запускает команды»](docs/ru/hooks.md#какая-оболочка-запускает-команды).
- Охрана PowerShell. Инструмент PowerShell в Claude Code (основной на Windows; на macOS и Linux включается
  `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`) проходит те же правила, что и Bash: `git push` в защищённые ветки,
  force, `--no-verify`, `git reset --hard`, рекурсивное удаление за пределами проекта; конструкция, которую
  охрана не может прочитать, получает `ask`. Хук `PreToolUse` теперь срабатывает на `Bash|PowerShell`. Охрана
  читает обёртки (`sudo`, `env`, `nohup`, `timeout`…) и префиксы `return`/`throw`/`exit`; смену расположения
  внутри блока или группы (каталог после неё неизвестен, если блок не вернулся туда, где начал, как парные
  `Push-Location … Pop-Location`), функции `cd..` и `cd\`, а смена расположения за обёрткой (`sudo cd x`)
  каталог не меняет; splatting `@p` в `Remove-Item`, `Start-Process` и `Set-Alias` (`ask`, кроме
  `-Recurse:$false`); `git`, оболочки, `pwsh`, `cmd`, `wsl` и `rm` с литеральными `@('…')`/`('…')`
  (раскрываются; остальные splat и группы — `ask`, у `git` при `push`/`commit`/`reset`); псевдонимы через диск
  `alias:`; код, собранный из строки (`[powershell]::Create().AddScript`,
  `[Management.Automation.ScriptBlock]::Create`, `.InvokeCommand.ExpandString`); `pwsh -File -` и
  `-WorkingDirectory`; `(git branch --show-current)` как текущую ветку. См.
  [«Охрана PowerShell»](docs/ru/guards.md#охрана-powershell).

### Fixed
- `forge` без `CLAUDE_PROJECT_DIR`, запущенный в worktree внутри основного checkout, больше не принимает
  основной checkout за корень проекта (с его состоянием и журналом): поиск профиля вверх не поднимается выше
  первого каталога с `.git`.
- Инструмент PowerShell не охранялся ни на одной ОС: `git push origin main` или `Remove-Item -Recurse` в нём
  проходили мимо forge. Теперь их проверяет [охрана PowerShell](docs/ru/guards.md#охрана-powershell).
- `protected_files` сопоставляются без учёта регистра: `.ENV`, `Secrets/Key.PEM` и `KEY.PEM` больше не обходят
  [охрану файлов](docs/ru/guards.md#охрана-файлов).
- [Охрана Bash](docs/ru/guards.md#охрана-bash) не видела команду за именем `git.exe` или `GIT`, за путём
  Windows (`C:\Git\cmd\git.exe`) и за обёртками с опциями (`nice -n 5`, `sudo -u root`, `timeout 10`, `xargs`,
  `/usr/bin/env git …`, `env -S`, `watch`). Теперь видит: строка `env -S` делится по правилам самого env
  (нечитаемая — `ask`), после неизвестной опции обёртки проверка переходит к охраняемой команде или вложенной
  обёртке, разбор обёрток линейный. `xargs` с `git push`/`commit`, `git reset` (кроме `xargs git reset --`),
  `rm -r`, оболочкой без скрипта, `pwsh`, `cmd` и `wsl` (кроме опций управления) получает `ask` (аргументы
  приходят из stdin); скрипт `-c` под `xargs` проверяется с учётом слов входа (`-I {}`, `"$@"`), так что
  `xargs -I{} sh -c 'git push origin {}'` — тоже `ask`. `wsl` охраняется: опции, `-e`/`--exec`, `--`,
  командная строка Linux проверяется как Bash. `pwsh` и `cmd`, запущенные из Bash, тоже проверяются; `cmd`
  читается с `/c`, `/k`, `/r`, без `^` и `"`, со слитыми ключами (`rd/s/q`) и разделителями `;`, `,`, `=`.
  В рекурсивном удалении читаются пути Windows и Git Bash. `cd`/`pushd`/`popd` в путь времени выполнения
  делают каталог неизвестным: относительный `rm -r` и `git push` без назначения из такого каталога получают
  `ask`; за обёрткой (`sudo cd`, `env pushd`, `timeout 5 cd`) они каталог не меняют. Длинные цепочки `cd`,
  `pushd`, `git -C` проверяются за линейное время, ветка каталога читается один раз за проверку.
  `$(git branch --show-current)` читается как текущая ветка, а `cd "$(git rev-parse --show-toplevel)"` — как
  корень проекта внутри него, если корень сам является верхним каталогом репозитория.

### Changed
- README (оба языка) переработан: навигация по разделам в шапке и ссылки «наверх», пошаговая установка для
  macOS, Linux и Windows, проверка установки после `/plugin install`.
- README (оба языка): нативный Windows с Git for Windows — отдельный путь установки рядом с WSL 2, охрана
  PowerShell в таблице возможностей.

### Обновление
- Windows без WSL: для проверки, формата и линта нужен Git for Windows (`winget install Git.Git`); если
  Claude Code не находит Git Bash, задай `CLAUDE_CODE_GIT_BASH_PATH` в `env` файла `settings.json`.
  `forge doctor` покажет, найден ли он. Без него шаги пропускаются, а не падают. Команды в `commands` пиши на
  синтаксисе POSIX `sh`. Скрипты, которые вызывают `forge verify`, учитывают новый код выхода 4 (шаги
  пропущены: нет Git Bash).
- Если в `protected_files` ты рассчитывал на учёт регистра (например, `.env` защищён, а `.ENV` нет), теперь
  совпадают оба написания; шаблоны менять не нужно, но проверь, что защита нужных файлов не стала шире, чем
  задумано.

## [0.4.0] — 2026-11-21

### Added
- Раздел профиля `release` — выпуски и журнал изменений, включаются по желанию: `changelog` (путь, по умолчанию
  `CHANGELOG.md`), `tag_prefix` (`v`), `version_files` (файлы с версией: путь — обработчик по имени для
  `*.json`, `pyproject.toml`, `Cargo.toml`, `pom.xml`, `*.csproj` — или `{ "path", "pattern" }` с регулярным
  выражением с одной группой захвата), `remind` (`true`), `ignore` (дописывается к встроенному списку: тесты,
  `docs/**`, Markdown, `.forge/**`). Без раздела всё ниже выключено. `forge init` предлагает раздел, если
  находит `CHANGELOG.md`, теги версий или CI, который публикует, запускается по тегам или вручную с параметром
  `publish`/`deploy`/`release`; в `version_files` попадают корневые файлы с версией не `0.0.0` и бейджи
  `version-x.y.z-` в корневых `README*.md`.
- Команда `forge release`: `--check [--json]` проверяет журнал в формате Keep a Changelog и файлы версий
  (ошибки с кодом выхода 1: `changelog-missing`, `no-unreleased`, `duplicate-version`, `version-order`,
  `version-file-unreadable`, `version-mismatch`; предупреждения: `bad-heading`, `bad-date`, `link-mismatch`,
  `tag-missing`); без аргументов — предпросмотр (уровень и причина, `текущая → следующая`, файлы, тег, коммит);
  `forge release <major|minor|patch|x.y.z> --yes` переносит `[Unreleased]` в `[x.y.z] — дата`, правит ссылки
  сравнения и файлы версий, делает коммит `chore(release): x.y.z` и аннотированный тег. Текущая версия — последняя
  в журнале, иначе последний тег версии, иначе наибольшая среди файлов версий (нет ничего — `0.0.0`); файл версии,
  который отличается от неё, — ошибка `--check`, а `--yes` в этом случае отказывает (версия не понижается молча).
  Заголовок новой версии повторяет разделитель предыдущего (` — ` или ` - `). Отказывается при грязном дереве,
  отсоединённом `HEAD`, репозитории без коммитов, пустом `[Unreleased]`, версии не больше текущей, существующем теге
  и ошибках раздела `release` в профиле (`--check` показывает их как `profile-invalid`); при сбое возвращает файлы
  и коммит, а если откат не удался, сообщает, в каком состоянии остался репозиторий. Ничего не пушит. Выпуск
  из пре-релиза, как в npm: `patch` у `1.0.0-rc.1` даёт `1.0.0`. Уровень по умолчанию выводится из разделов `[Unreleased]` и пометок в записях
  (правила — в docs/ru/releases.md): `Added`/`Changed` — minor, остальное — patch, ломающие изменения — major; нестандартные
  разделы его не поднимают, до 1.0 major заменяется на minor. `--date`, `--json`; код выхода 2 при ошибке в использовании.
- Напоминание в хуке `Stop`: если за ход менялся код (файлы вне `release.ignore`), а в `[Unreleased]` нет записей,
  ход не завершается и модель просит добавить запись или сказать, что она не нужна. Один раз на ветку, на ветке
  по умолчанию — один раз на последний тег версии; память `release.reminded`. Выключается `release.remind: false`.
- Скилл `/forge:release`: проверка, чтение `[Unreleased]` с предложением правок формулировок (принятые правки
  коммитятся до выпуска — `--yes` требует чистое дерево), уровень вместе с пользователем, `forge release --yes`,
  push и шаги проекта после тега (публикация, деплой, GitHub-релиз) — только с явного согласия и только описанные
  в документации проекта; если ничего не описано, предлагается лишь GitHub-релиз (при `gh` и GitHub-remote). Если
  push отклонён охраной forge (защищённая ветка), скилл так и говорит и предлагает отправить только тег или
  принятый в проекте порядок, не обходя охрану.
- `reviewer` при разделе `release` отмечает заметное пользователю изменение без записи в `[Unreleased]`;
  `/forge:init` рассказывает о предложенном разделе и предлагает завести `CHANGELOG.md`.
- Строка о журнале изменений в `forge doctor` (при разделе `release`).
- forge отвечает на языке пользователя — английском или русском: вывод CLI, причины хуков, ошибки профиля,
  замечания `forge docs` и `forge release --check`, заметки `forge init`. Язык выбирается по порядку:
  переменная `FORGE_LANG` (`en`/`ru`), поле профиля `language` (`auto` по умолчанию, `en`, `ru`), последнее
  сообщение пользователя в транскрипте сессии (без блоков кода, вставок, логов и URL; служебные записи Claude Code
  не считаются; доля кириллицы от 0,3 — русский; короткое «да» — смотрим предыдущее), язык,
  который хук `Stop` запомнил в `state.lang` (для CLI, где транскрипта нет), локаль `LC_ALL`/`LC_MESSAGES`/`LANG`,
  иначе английский. Логи, скиллы и агенты остаются английскими. Подробности — в разделе «Язык сообщений»
  страницы `docs/ru/hooks.md`.

### Changed
- README сокращён до обзора; справка разнесена по страницам `docs/en/` и `docs/ru/` (хуки, охрана, профиль,
  маршрутизация с разделом про другие модели, агентские файлы, выпуски, скиллы, CLI, состояние, разработка).
- Напоминания хука `Stop` (про агентские файлы и про пустой `[Unreleased]`) читают одно общее окно правок
  (курсор `docs.offset`), и если сработали оба, Claude получает один блок с обеими причинами. Проверка (`verify`)
  по-прежнему важнее. Курсор `state.docs` удаляется, только когда выключены оба напоминания.

### Обновление
- Ничего менять не нужно: без раздела `release` поведение прежнее. Чтобы включить выпуски, запустите
  `forge init` (покажет предлагаемый раздел; существующий профиль без `--force` он не меняет, так что раздел
  переносится в `.forge/profile.json` вручную) или добавьте в профиль `"release": {}` и при необходимости
  `version_files`. Проверить настройку — `forge release --check`.
- Язык сообщений: ничего делать не нужно — forge сам подстроится под язык, на котором вы пишете. Чтобы закрепить
  язык, добавьте в профиль `"language": "ru"` (или `"en"`); на один запуск — `FORGE_LANG=ru`. Раньше все сообщения
  были русскими, теперь без закреплённого языка англоязычный пользователь получит английские.

## [0.3.0] — 2026-11-21

### Added
- Схема агентских файлов: `AGENTS.md` — источник, рядом `CLAUDE.md` из одной строки `@AGENTS.md`, в том числе
  во вложенных каталогах. Вложенный `CLAUDE.md` Claude Code подгружает по требованию, поэтому шим нужен и там.
- Команда `forge docs [--fix] [--json]`: детерминированная проверка `AGENTS.md`/`CLAUDE.md`. Ошибки (код выхода 1):
  `missing-root`, `missing-shim`, `no-import`. Предупреждения: `claude-only`, `fat-claude`, `too-long`,
  `unlisted`, `broken-link`, `verify-undocumented`, `incomplete-scan`. `--fix` создаёт недостающие и пустые
  `CLAUDE.md` со строкой `@AGENTS.md` и больше ничего не пишет; исправимое замечание, которое он не стал чинить,
  печатается строкой `пропущен <путь>: <причина>`. `CLAUDE.md` — символическая ссылка на соседний `AGENTS.md` —
  считается правильной ссылкой; игнорируемые git файлы рядом с найденными тоже учитываются. Строка о состоянии
  агентских файлов есть и в `forge doctor`.
- Напоминание в хуке `Stop`: если за ход поменялись команды или структура проекта (файлы из `docs.watch`,
  `scripts` в `package.json` против `HEAD` репозитория его каталога, новый каталог верхнего уровня, которого нет
  в корневом `AGENTS.md`), а агентские файлы не правились, ход не завершается и модель просит проверить, не
  устарели ли они. Курсор `docs.offset` уходит в конец журнала после каждой остановки; память `docs.reminded`
  (отпечаток `scripts` на каждый `package.json`, имена новых каталогов) не даёт напомнить об одном и том же
  дважды — правка одних зависимостей после напоминания молчит. Проверка (`verify`) важнее — при её падении
  напоминания нет.
- Начало сессии: строка, если нет корневого `AGENTS.md` или `CLAUDE.md` его не подключает.
- Поле профиля `docs`: `remind` (напоминание, по умолчанию `true`), `max_lines` (предел длины файла, 200),
  `watch` (дописывается к встроенному списку файлов).
- Скилл `/forge:docs`: создать, перенести и разделить агентские файлы с резервной копией и проверкой, что текст
  не потерян; `guide.md` — когда нужен вложенный файл. `/forge:init` предлагает его (или `forge docs --fix`) в
  конце настройки.
- README на английском (`README.md`) и русском (`README.ru.md`) с переключателем языка, оглавлением,
  переходами между разделами и схемой жизненного цикла хуков.

### Changed
- Журнал правок `.forge/edits.jsonl` получил третий курсор — `docs.offset` в `state.json`. Журнал обнуляется,
  когда догнали все действующие курсоры; отсутствующий `docs.offset` обнуление не задерживает, а при
  `docs.remind: false` `Stop` удаляет `state.docs`.

### Обновление
- Профиль менять не нужно. Первая остановка после обновления только заводит курсор `docs.offset`, напоминаний о
  правках до неё не будет. Не нужно напоминание — `"docs": { "remind": false }`.
- В проекте, где уже есть вложенные `AGENTS.md` без соседних `CLAUDE.md`, запусти `forge docs --fix`: Claude Code
  читает `CLAUDE.md`, а не `AGENTS.md`, и без этой ссылки правила области не подтягиваются. Остальные замечания
  `forge docs` — через `/forge:docs`.
- Вложенный git-репозиторий (отдельный `.git` в подкаталоге) из родительского `forge docs` не видит — запускай
  его внутри вложенного репозитория.

### Added
- Роль `senior` для задач плана, которые нельзя описать до конца или где тонкая ошибка дорога: конкурентность
  и протоколы, изменение чужого контракта, `risky_paths`, область без тестов. Исполняет её агент
  `implementer`; модели — eco `sonnet/high`, normal `opus/high`, max `opus/xhigh`. `forge:plan` получил
  критерии выбора и правило «senior — не больше трети задач».
- Лестница повторов в `forge:execute`: первый повтор после падения — ступенью выше с логом
  (mechanic → implementer → senior, остальные роли — той же ролью), второе падение — `debugger`.
- В начале сессии forge сообщает, что переопределения `routing` из профиля проигнорированы, и отсылает к
  `forge doctor`.
- Репозиторий: технический README, `AGENTS.md` для агентов, этот журнал, лицензия MIT, проверка `npm test`
  в GitHub Actions на каждый push в `main` (Node 20, 22, 24).

### Changed
- Проверки таблицы маршрутизации: senior не слабее implementer, reviewer и debugger не слабее senior.
  Встроенная таблица держит senior строго сильнее implementer. Сообщения об ошибках подсказывают, какую
  строку профиля поправить.

### Fixed
- Охрана Bash не видела команды внутри подстановки `$(...)`, обратных кавычек и `<(...)`/`>(...)`:
  например, `echo $(git push --force origin main)` проходил без проверки. Теперь они проверяются так же, как
  `bash -c "…"`, в том числе в теле heredoc с некавыченным разделителем.
- Вложенность раньше проверялась неодинаково: `bash -c` разбирался только до глубины меньше 2, а более глубокая
  вложенность пропускалась без проверки. Теперь `bash -c`, `eval` и подстановки делят один предел в три уровня,
  глубже — запрос подтверждения (`ask`). Так же — незакрытая подстановка и вход, который разборщик не может
  проследить.
- Охрана Bash читала команду не так, как bash, и пропускала обходы: `$'git' push --force origin main`
  (ANSI-C кавычки), `$\⏎(…)` и другие места, где bash склеивает `\` + перевод строки, терминатор heredoc
  `<<EOF` с ведущей табуляцией (табуляции снимает только `<<-`), сдвиг `<<` внутри `((…))` и `for ((…))`,
  который принимался за heredoc и прятал следующие строки. Теперь это разбирается как в bash.
- `eval` (в том числе `eval -- …`) проверяется как `bash -c`. У `bash`/`sh`/`zsh`, а теперь и `dash`/`ksh`, флаг `-c` находится в любой
  связке (`-lc`, `-xc`, `-cx`), значения `-o`/`-O` пропускаются, `--` тоже.
- Сокращённые длинные опции git (`--forc`, `--no-verif`, `--mi`, `--al`, `--ha`) читаются как полные
  `--force`, `--no-verify`, `--mirror`, `--all`, `--hard` и больше не обходят охрану.
- Охранные хуки `pre-bash` и `pre-edit` закрываются при собственной ошибке: вместо молчаливого пропуска они
  отвечают `ask`. Раньше, например, `protected_files: ["{*}"]` ломал сопоставление шаблонов, и хук разрешал
  любую правку.
- `git push --force --force-with-lease` проходил охрану, хотя `--force` отменяет проверку аренды и git делает
  обычный force push. Теперь явный `--force`, `-f` или `+refspec` запрещён и вместе с арендой.
- Ошибки формата и линта после правок не доходили до Claude: хук `PostToolBatch` отвечал `decision: block`,
  а для этого события Claude Code обрывает ход и показывает причину только пользователю. Теперь ошибки
  приходят Claude как контекст перед следующим шагом, ход не прерывается.

### Обновление
- Переопределения `routing` в `.forge/profile.json` теперь проверяются и против `senior`. Если в каком-то
  режиме reviewer или debugger ниже senior (в normal — ниже `opus/high`) или implementer выше senior, forge
  игнорирует весь блок `routing`. После обновления запусти `forge doctor`: строка `routing:` назовёт, что
  поправить.
