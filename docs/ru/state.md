# Файлы и состояние

Что forge хранит в `.forge/` в корне проекта. Какие из этих файлов создаёт [`forge init`](profile.md#что-пишет-init) и какие попадают в `.git/info/exclude` — на странице профиля.

## Каталог .forge

```
.forge/
├── profile.json          профиль (коммит — по желанию)
├── profile.schema.json   копия config/profile.schema.json
├── state.json            состояние сессии                        ┐
├── edits.jsonl           журнал правок                           │ в .git/info/exclude
├── work/<slug>/          spec.md, plan.md, review.md             │
└── log/errors.log        внутренние ошибки хуков                 ┘
```

## Файл состояния

`state.json`: `tier` (0–3, по умолчанию 1), `stage`, `mode` (`null` — из профиля), `task.slug`, `artifacts.spec` и `artifacts.plan`, `verify` (`at`, `ok`, `summary`, `failed_step`, `edits_offset`, `notified`), `failures.verify_streak`, `lint_offset`, `docs.offset` (курсор, общий для обоих [напоминаний `Stop`](hooks.md#напоминания-в-конце-хода)), `docs.reminded` ([память напоминаний](agent-docs.md#память-о-напоминаниях)) и `release.reminded` (ключи [напоминания про выпуск](releases.md#напоминание-про-пустой-unreleased): список из не более чем 20 строк) и `lang` (`en` или `ru`: язык вашего последнего сообщения, который хук `Stop` запоминает в проекте с профилем, чтобы CLI, у которого нет транскрипта, [отвечал на нём](hooks.md#язык-сообщений)). Меняется только через [`forge state`](cli.md#команды) и хуки; повреждённый файл заменяется значениями по умолчанию. `forge state set`, `forge state reset` и `forge mode <режим>` создают его и без профиля.

## Журнал правок

`edits.jsonl`: строка `{"t": <мс>, "f": "<путь от корня>"}` на правку. [Линт](hooks.md#формат-и-линт-после-правок), [проверка](hooks.md#автопроверка-при-завершении-хода) и [напоминания `Stop`](hooks.md#напоминания-в-конце-хода) хранят свои байтовые курсоры (`lint_offset`, `verify.edits_offset`, `docs.offset`; напоминания про агентские файлы и про выпуск делят последний). Когда все действующие курсоры догнали конец, а журнал не меньше 256 КБ, он обнуляется, и курсоры сбрасываются в 0. Курсора `docs.offset` может не быть (первая остановка после обновления; когда оба напоминания выключены, `Stop` удаляет `state.docs`) — тогда он не мешает обнулению; пока он есть и отстаёт, журнал сохраняется.

Состояние — одно на рабочую директорию. Параллельные сессии запускай в отдельных worktree. В linked worktree без своего профиля forge [берёт профиль основного checkout](profile.md#профиль-в-worktree), но `state.json`, журнал правок, `log/` и планы `work/` у worktree свои: каталог `.forge/` в нём появляется при первой записи. Продолжить в worktree план основного checkout — скопируй его каталог `.forge/work/<slug>/`.

## Ограничения

- Журнал правок обнуляется, только когда догнали все действующие курсоры (`verify.edits_offset`, `lint_offset`, `docs.offset`, если он есть; последний общий для обоих напоминаний `Stop`). Курсор потребителя, который не работает (нет команд `format`/`lint`, `verify.on_stop: "off"`), остаётся 0 и не даёт обнулить журнал — так было и до `forge docs`.
- Одна сессия на рабочую директорию: две сессии в одном checkout делят `.forge/state.json` и журнал правок.
- В журнал пишут только инструменты правки ([ограничения хуков](hooks.md#ограничения)).
