## `/forge:init`

- **Кто вызывает:** только пользователь.
- **Артефакты и состояние:** `.forge/profile.json`, `.forge/profile.schema.json`, `.git/info/exclude`.

[Определяет стек](profile.md#автоопределение-стека), согласует и пишет профиль, запускает `forge doctor`, затем `forge docs`: при `missing-root` предлагает `/forge:docs`, при `missing-shim` — `forge docs --fix`. Если `forge init` предложил [раздел `release`](releases.md#как-включить), говорит, почему, и предлагает создать отсутствующий `CHANGELOG.md`.

## `/forge:mode`

- **Кто вызывает:** только пользователь, как `/forge:mode [eco|normal|max]`.
- **Артефакты и состояние:** `mode` в `.forge/state.json`.

Показывает или переключает [режим и таблицу](routing.md#модели-по-режимам).

## `/forge:plan`

- **Кто вызывает:** модель (фича или правка на несколько файлов) или пользователь.
- **Артефакты и состояние:** `.forge/work/<slug>/spec.md`, `plan.md`; `task.slug`, `stage: plan`, `tier` 2 (3 — если задеты [`risky_paths`](profile.md#поля-профиля)), `artifacts.spec`, `artifacts.plan`.

Контекст через `scout`, до трёх вопросов, спека до ~40 строк, план задач с [ролями](routing.md#роли), проверками и группами для параллельного запуска ([формат](#формат-задачи-в-плане)); ждёт «да».

## `/forge:execute`

- **Кто вызывает:** модель или пользователь.
- **Артефакты и состояние:** отметки `[x]` в `plan.md`; `stage: execute`, затем `review`.

Готовые задачи — ролям через `forge route`, с непересекающимися файлами — параллельно; отмечает задачу только после прошедшей `check` (если отчёт её не показывает — запускает сам); [лестница повторов](routing.md#лестница-повторов); в конце `forge verify` и `forge:review` (всегда на уровне 3, на уровне 2 — если пользователь не отказался).

## `/forge:docs`

- **Кто вызывает:** модель или пользователь.
- **Артефакты и состояние:** файлы `AGENTS.md`/`CLAUDE.md`, резервная копия; состояние не меняет.

Заводит, переносит и делит [агентские файлы](agent-docs.md#схема-файлов) по схеме «AGENTS.md — источник, CLAUDE.md подключает его» (создать, перенести из корневого `CLAUDE.md` или чужих файлов правил, разделить длинное, починить ссылки). Начинает с `forge docs --json`, читает файлы сама, область исследует через `scout`; черновик показывает и ничего не пишет без «да». Перед правкой копирует затронутые файлы в `.forge/work/docs-backup/<время>/` (в git — при незаигнорированном `.forge/work/` в `<git-common-dir>/forge-docs-backup/<время>/`), переносит текст дословно и сверяет, что ни одна строка не пропала.

## `/forge:review`

- **Кто вызывает:** модель или пользователь.
- **Артефакты и состояние:** `.forge/work/<slug>/review.md` (без активной задачи — `.forge/work/review.md`); `stage: review`.

База — `git merge-base` с защищённой веткой; reviewer через `forge route` (дифф больше ~800 строк — несколько параллельно по областям); перепроверяет blocker и major; показывает находки по серьёзности и спрашивает, что чинить. При разделе `release` ревьюер отмечает и заметное пользователю изменение без записи в `[Unreleased]`.

## `/forge:release`

- **Кто вызывает:** модель (когда вы просите выпустить версию) или пользователь.
- **Артефакты и состояние:** журнал, файлы версий, коммит и тег; состояние не меняет.

Выпускает проект с разделом `release`: `forge release --check`, чтение `[Unreleased]` с предложением правок формулировок, уровень вместе с вами, `forge release <уровень> --yes`, затем push только после вашего согласия; шаги, специфичные для проекта (GitHub-релиз, публикация, деплой), — только если они описаны и только с вашего явного согласия. См. [Выпуск через Claude](releases.md#выпуск-через-claude).

## Формат задачи в плане

```markdown
- [ ] T1 <imperative title>
  role: implementer
  files: src/a.ts, src/a.spec.ts
  check: npm test -- a.spec
  depends: -
```

`role` — `implementer`, `mechanic`, `senior` или `scout`; `senior` — не больше трети задач плана. Агенты не коммитят, не пушат и не переключают ветки — git остаётся за основной сессией.

## Ограничения

- `risky_paths`, уровни задач и `tdd` в 0.3.0 — подсказки для скиллов; хуки их не применяют. Как скиллы вызывают роли — в [ограничениях маршрутизации](routing.md#ограничения).
